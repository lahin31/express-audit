# LOG001 — Sensitive Data in Logs

| Property     | Value      |
|--------------|------------|
| **ID**       | LOG001     |
| **Severity** | ⚠️ High   |
| **Category** | Logging    |
| **Detector** | AST        |

## Description

Sensitive properties — passwords, tokens, API keys, session IDs — are passed to a logging call (`console.log`, `logger.info`, etc.).

## Why It Matters

Application logs are frequently:

- Shipped to log aggregation services (Datadog, Splunk, ELK).
- Stored on disk with broad read permissions.
- Included in support tickets, screen-shares, and debugging sessions.
- Retained for 90+ days.

Any secret written to a log is effectively broadcast. A single access to log storage exposes credentials for every user who logged in during the retention window.

## Vulnerable Examples

```typescript
// ❌ Password in plain sight
console.log('Login attempt:', email, password);

// ❌ Token logged on sign-in
logger.info({ event: 'oauth_callback', token: accessToken });

// ❌ Entire request body (may contain any sensitive field)
app.use((req, res, next) => {
  console.log('Request body:', req.body);
  next();
});

// ❌ Authorization header
console.log('Headers:', req.headers.authorization);
```

## Secure Example

```typescript
// ✅ Log only safe, non-sensitive fields
console.log('Login attempt:', email); // no password

// ✅ Use a log sanitizer for structured objects
import { createLogger } from 'winston';

const SENSITIVE_KEYS = new Set([
  'password', 'token', 'secret', 'authorization',
  'access_token', 'refresh_token', 'api_key',
]);

function sanitize(obj: Record<string, unknown>): Record<string, unknown> {
  return Object.fromEntries(
    Object.entries(obj).map(([k, v]) => [
      k,
      SENSITIVE_KEYS.has(k.toLowerCase()) ? '[REDACTED]' : v,
    ]),
  );
}

logger.info({ event: 'login', user: sanitize(req.body) });

// ✅ Log specific safe fields from request body
logger.info({
  event: 'user_created',
  userId: newUser.id,
  email: newUser.email,
  // no password, no tokens
});
```

## Remediation

1. Never pass `password`, `token`, `secret`, or similar fields to any log call.
2. Never log `req.body` wholesale — always select specific fields.
3. Strip `Authorization` headers from request logs.
4. Use a structured logger (Winston, Pino) with a redaction plugin:
   - [pino-noir](https://github.com/pinojs/pino-noir)
   - [winston-sanitize](https://github.com/levelops/winston-sanitize)
5. Audit your log aggregation system for retained sensitive data.
