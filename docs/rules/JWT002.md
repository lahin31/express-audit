# JWT002 — JWT Missing Expiration

| Property   | Value            |
|------------|------------------|
| **ID**     | JWT002           |
| **Severity** | ⚠️ High        |
| **Category** | Authentication |
| **Detector** | AST            |

## Description

A JWT token is issued without an expiration time (`expiresIn` option is missing). Tokens without an expiry remain valid indefinitely.

## Why It Matters

If a token is stolen (via XSS, man-in-the-middle, or database breach) it can be used forever. Short-lived tokens limit the window an attacker has to exploit a compromised credential.

## Vulnerable Example

```typescript
// ❌ Token never expires
const token = jwt.sign({ userId: user.id }, process.env.JWT_SECRET);

// ❌ Options object exists but expiresIn is not set
const token = jwt.sign({ userId: user.id }, process.env.JWT_SECRET, {
  algorithm: 'HS256',
});
```

## Secure Example

```typescript
// ✅ Short-lived access token
const accessToken = jwt.sign({ userId: user.id }, process.env.JWT_SECRET, {
  expiresIn: '15m',
});

// ✅ Separate longer-lived refresh token with rotation
const refreshToken = jwt.sign(
  { userId: user.id, type: 'refresh' },
  process.env.REFRESH_TOKEN_SECRET,
  { expiresIn: '7d' },
);
```

## Remediation

1. Always set `expiresIn` on `jwt.sign()`.
2. Use short expiry times for access tokens (15 minutes is common).
3. Use refresh tokens with rotation for longer sessions.
4. Store refresh tokens server-side so they can be revoked.
