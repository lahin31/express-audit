# ERR001 — Raw Error Object Returned to Client

| Property     | Value           |
|--------------|-----------------|
| **ID**       | ERR001          |
| **Severity** | 📋 Medium      |
| **Category** | Error Handling  |
| **Detector** | AST             |

## Description

A raw error object, or a response object containing `err.stack`, is returned directly in an HTTP response. This exposes internal implementation details to clients.

## Why It Matters

Stack traces reveal:

- **Source file paths** — directory structure and framework versions.
- **Line numbers** — exact location to target for further exploitation.
- **Dependency names and versions** — enables targeted CVE lookups.
- **Internal hostnames** — database server names, internal service URLs.

This violates the security principle of *minimum information disclosure*.

## Vulnerable Examples

```typescript
// ❌ Sending the raw error object
app.use((err: Error, req: Request, res: Response, next: NextFunction) => {
  res.status(500).json(err);
});

// ❌ Including the stack trace
app.use((err: Error, req: Request, res: Response, next: NextFunction) => {
  res.status(500).json({
    message: err.message,
    stack: err.stack,       // Full stack visible to client
  });
});

// ❌ Leaking database error details
app.get('/user/:id', async (req, res) => {
  try {
    const user = await db.findById(req.params.id);
    res.json(user);
  } catch (err) {
    res.status(500).json({ error: err }); // DB error message exposed
  }
});
```

## Secure Example

```typescript
import { logger } from './logger.js';

// ✅ Log internally, return generic message to client
app.use((err: Error, req: Request, res: Response, next: NextFunction) => {
  // Log the full error server-side with a correlation ID
  const errorId = crypto.randomUUID();
  logger.error({
    errorId,
    message: err.message,
    stack: err.stack,
    url: req.url,
    method: req.method,
  });

  // Return only a generic message + correlation ID to the client
  res.status(500).json({
    error: 'An unexpected error occurred.',
    errorId,  // Lets support staff correlate without exposing details
  });
});
```

## Remediation

1. Replace `res.json(err)` and `res.json({ stack: err.stack })` with generic messages.
2. Log the full error server-side using a structured logger.
3. Include a correlation/error ID in both the log and the response for supportability.
4. Differentiate between operational errors (expose safe message) and programmer errors (always 500 + generic).
5. In development, you may optionally include more details — gate it on `process.env.NODE_ENV !== 'production'`.
